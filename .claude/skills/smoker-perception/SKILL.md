# 흡연자 인식 구현 가이드

> 이 문서는 ROS2 이식(단계 B) 기준이다. Windows 웹캠 프로토타입(단계 A)과 core/래퍼 구조는 `windows-prototype` 스킬을 먼저 따른다. 아래 1~5번 로직은 `ash_e_core`에 이미 있으므로 다시 쓰지 말고 호출만 하며, ROS 래퍼에서는 입력 변환, 뎁스 융합(6번), 발행(7번)만 구현한다.

## 왜 2단계 구조인가
담배는 전체 화면에서 몇 픽셀에 불과해 단일 검출기로는 재현율이 낮다. 사람 검출로 후보를 좁힌 뒤 손·얼굴 주변 ROI에서 담배를 보면 작은 객체 문제와 연산량을 함께 줄일 수 있다. 설계서가 다른 구조를 정했다면 설계서를 우선한다.

## 파이프라인
1. **입력**: 컬러 이미지 + 정렬된 뎁스(`aligned_depth_to_color`) + CameraInfo. 카메라 없이 재생 모드(rosbag/이미지 폴더)도 지원한다.
2. **사람 검출**: 경량 YOLO(n/s 계열)를 ONNX Runtime 또는 NCNN으로 실행한다. RPi5는 GPU가 없으므로 입력 320~416px, 프레임 스킵(예: 2프레임당 1회) 파라미터를 둔다.
3. **ROI 분석**: 사람 박스 안에서 얼굴·손 ROI를 구해(포즈 키포인트 또는 박스 비율) 담배 검출/분류기를 돌린다.
4. **상태 판정**: 담배가 입 근처(`smoking`)인지 손 근처(`holding`)인지 키포인트 거리로 가른다.
5. **시간 안정화**: 사람별 최근 N프레임 중 M프레임 이상 양성일 때만 확정한다. 한 프레임 오검출로 로봇이 움직이는 것을 막기 위해서다.
6. **3D 위치**: 사람 박스 하단부를 제외한 ROI의 뎁스 중앙값(0과 범위 밖 값 제거)을 거리로 쓰고, 카메라 내부 파라미터로 `(x, y, z)`를 계산해 설계서가 정한 frame_id로 발행한다.
7. **발행**: 설계서의 메시지 정의를 따른다. 사람 ID는 간단한 IoU/거리 기반 트래커로 프레임 간 유지한다.

## 구현 규칙
- 패키지: `src/ash_e_perception/` (ament_python). 파라미터는 `config/*.yaml`.
- 추론 시간·FPS를 주기적으로 `get_logger().info`로 남긴다.
- 모델 파일이 없어도 노드가 기동하고 빈 결과를 내도록 한다(통합 테스트 용이).
- 모델 학습이 필요하면 학습 스크립트와 데이터 구조는 `training/`에 분리하고 노드 코드와 섞지 않는다.

## 흔한 실패
- 뎁스 0값(측정 불가)을 거리로 그대로 사용 → 중앙값 계산 전에 반드시 제거한다.
- 컬러/뎁스 해상도 불일치 → 정렬된 뎁스 토픽을 쓰거나 좌표를 변환한다.
- 입력 큐 적체로 지연 증가 → QoS depth 1, 최신 프레임만 처리한다.
